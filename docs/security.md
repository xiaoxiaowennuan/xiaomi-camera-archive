# 安全模型

## 核心不变量

1. 原始录像永久只读，任何代码、测试、转码或部署流程都不得修改其内容、名称、权限或 metadata。
2. 数据库、密码哈希、session、缓存、临时文件、日志和前端构建产物位于独立状态目录。
3. 客户端只能使用数据库发放的不可猜测公开 ID 访问媒体，不能提交路径、文件 URL 或任意文件名。
4. 除登录页、静态资源和健康检查外，页面、API、缩略图与视频流全部要求有效应用 session。
5. 默认不暴露公网；公网访问必须经过受信任 TLS 终止层。

## 资产和信任边界

- 高价值资产：家庭录像、缩略图、事件时间、认证会话和部署密钥。
- 不可信输入：HTTP 参数、URL 状态、媒体公开 ID、数据库外部文件、损坏媒体、被篡改的目录项和 ffprobe/ffmpeg 输出。
- 受控可写区：SQLite、转码缓存和应用临时目录。
- 只读区：媒体 bind mount。
- 管理边界：管理员密码通过 secret 文件引导，真实媒体库路径和公网代理配置只存在于未跟踪部署配置中。

## 路径和媒体读取

- 部署只读挂载专用媒体库根；文件夹路径必须是该根或其后代，且解析 symlink 后仍在根内。
- scanner 只索引预期子目录中的普通文件，使用 `Lstat` 拒绝 symlink 和特殊文件。
- 数据库只保存规范化相对路径。扫描时和每次打开时都验证路径仍位于相应根目录，且目标仍是普通非 symlink 文件。
- HTTP 路由只接受固定格式公开 ID；查不到 ID 返回统一 404。
- 禁止提供 `/download?path=...`、目录浏览、任意 URL 抓取或调试文件读取接口。
- Range 和 HEAD 只作用于已经由 ID 映射且重新验证的文件。
- API 和播放器永不返回媒体相对路径；服务器绝对路径仅向管理员文件夹管理接口返回，普通用户不可见。

仅靠字符串 `Clean` 不足以抵御 symlink 和竞态。实现应使用根目录约束的打开方式；部署时只读挂载进一步阻止目录项变化，但不能替代应用校验。

## 索引与子进程

- ffprobe/ffmpeg 使用参数数组执行，不经 shell，不拼接客户端输入。
- 输入路径只能来自索引记录；输出路径只能由应用在 `STATE_DIR` 内生成。
- 子进程设置超时、并发上限和资源友好的默认值；stderr 截断并脱敏后才记录。
- 扫描失败不得修改媒体。只有完整扫描成功后才提交缺失标记，避免部分失败破坏索引。
- SQLite 启用外键、busy timeout，并采用参数化查询；迁移在事务中执行。
- 转码临时文件使用安全随机名和限制权限，完成后原子改名。失败清理只允许命中已验证的状态目录内单个临时文件。

## Web 和 API

- 默认 `LISTEN_ADDR=127.0.0.1:8080`。
- 查询参数限制时间跨度、分页大小和字符串长度；未知字段与非法编码返回 400。
- JSON 使用明确结构和 content type；用户可见错误不包含 SQL、路径、命令或堆栈。
- 状态改变操作使用 POST/PUT，并强制校验 `Origin` 与请求 Host 同源。
- 设置 CSP、`X-Content-Type-Options: nosniff`、合理 Referrer Policy 和 frame 限制。
- 媒体响应使用准确 content type，不允许用户控制响应头或文件名。
- 受控 URL 状态只含日期、时间、事件公开 ID；不把敏感状态写入 fragment、日志或分析平台。

## 认证和公网边界

- 密码使用 Argon2id 与随机 salt 哈希，数据库不保存可逆密码。
- SCS 生成高熵服务端 session token；cookie 为 HttpOnly、SameSite=Strict，HTTPS 部署必须启用 Secure。
- 登录成功后轮换 session token，退出时销毁 session；会话有绝对有效期和空闲超时。
- 用户修改密码必须提供旧密码和两次一致的新密码；成功后清除现有 session，旧密码错误按账号和客户端地址限速。
- 登录错误不区分用户不存在与密码错误，并按客户端地址和用户名做短时失败限速。
- `admin` 可新增用户和维护文件夹；普通用户只能列出文件夹并访问录像。
- 初始管理员密码仅从未跟踪 secret 文件读取，并且只在用户表为空时生效，不会在重启时重置账号。
- 公网仍应通过 TLS 反向代理、隧道访问控制或额外 MFA 层；应用不信任客户端伪造的转发身份头。

## 容器加固

后续 Compose 部署必须满足：

- 专用媒体库使用精确只读 bind mount，例如 `/host/camera-library:/media-library:ro`；不得挂载整块磁盘或宽泛系统目录。
- 状态目录单独可写挂载，不挂载宿主机根、home、SSH 目录或 Docker socket。
- 非 root UID/GID，`cap_drop: [ALL]`，`security_opt: [no-new-privileges:true]`。
- 不使用 `privileged`、host PID/IPC 或不必要的 host network。
- 尽可能启用只读 root filesystem，并为 `/tmp` 使用限制大小的 tmpfs。
- 镜像固定版本或 digest，依赖许可证和漏洞在升级时检查。

## 日志和隐私

- 只记录公开 ID、时间范围、耗时、状态码和稳定错误码。
- 不记录绝对/相对媒体路径、请求 cookie、Authorization、Tunnel token、原始 ffmpeg 命令或媒体内容。
- 事件时间本身具有隐私性；生产日志默认不逐事件输出。
- 不提交数据库、缓存、真实 session、密钥、家庭网络地址或任何媒体样本。

## 威胁与控制

| 威胁 | 主要控制 |
| --- | --- |
| 路径穿越或任意文件读取 | 公开 ID 映射、根目录约束打开、拒绝 symlink、无 path API |
| 原始录像被应用覆盖 | 只读挂载、状态目录隔离、输出路径固定、非 root |
| 恶意媒体利用探测器 | 进程超时、资源限制、最小权限、依赖更新、错误隔离 |
| 转码并发导致资源耗尽 | 幂等任务、单 worker 默认值、缓存上限、请求限流 |
| 缓存文件被当作源媒体 | 独立根目录和独立 API variant，禁止反向映射 |
| 未认证公网访问 | 应用全路由 session 校验、回环监听、TLS 反向代理或受控隧道 |
| session 劫持或 CSRF | 服务端 session、HttpOnly/SameSite cookie、登录轮换、同源校验、TLS |
| 管理员配置任意宿主机路径 | 部署时固定只读媒体库根、根内映射、symlink 边界验证、无 Docker socket |
| 日志泄露家庭信息 | 路径与事件脱敏、凭据过滤、低详细度生产日志 |
| 数据库被篡改后越界读取 | 每次打开重新做根目录和文件类型校验 |

## 安全验证清单

- 路径穿越：绝对路径、`..`、双重编码、分隔符变体和无效 UTF-8。
- symlink：扫描时 symlink、扫描后替换、缩略图 symlink 和状态目录逃逸。
- ID：未知、截断、超长、大小写变化和非 URL-safe 字符。
- Range：越界、多范围、空文件和并发请求。
- 转码：重复 POST、进程失败、超时、磁盘上限和临时文件清理。
- 日志：断言错误响应和日志都不包含媒体根、相对路径或命令参数。
- 部署：验证媒体挂载为 `ro`、非 root、无额外 capability、无 Docker socket。
